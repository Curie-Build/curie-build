Tools · curie dev

Dev mode

curie dev runs your application in exploded form — straight from compiled class files, without packaging a JAR — and restarts it automatically whenever a source file changes.

Usage

shell 
$ curie dev

Pass arguments to the application after --:

shell 
$ curie dev -- --server.port=9090 --spring.profiles.active=dev

What happens on startup

$ curie dev 
Dev hello v0.1.0
  Compile         3 source file(s)
  ▸ Watching      com.example.Hello

Hello, Curie.
  1. Compile — sources are compiled to target/classes/. No JAR is written.
  2. Launch — the JVM is started as java -cp target/classes:<deps> com.example.Hello.
  3. Watch — curie watches src/ and Curie.toml for changes. On Linux, inotify delivers near-instant notifications; on other platforms, curie polls every 300 ms.

Automatic restart on change

When any file under src/ or Curie.toml is saved, curie:

  1. Kills the running JVM process.
  2. Recompiles all sources.
  3. Relaunches the application with the same classpath and arguments.
after editing Hello.java 
  ▸ Restarting    source changed
  Compile         3 source file(s)  [source changed]
  ▸ Watching      com.example.Hello

Hello, updated Curie.

If the recompile fails, the process stays down and curie keeps watching. Save the file again once the error is fixed — curie will retry immediately.

Exploded form vs. JAR

curie run packages a self-contained JAR before launching; curie dev skips that step and points the JVM directly at target/classes/. The difference:

curie runcurie dev
Packages a JARYesNo
Runs testsYesNo
Docker supportYesNo
Classpath-jar target/app.jar-cp target/classes:deps…
Restart on changeNoYes (inotify on Linux; 300 ms poll elsewhere)

Remote debugging

Pass the JVM debug agent via --. Java 21 and newer support the simplified form:

shell 
$ curie dev -- -agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=*:5005

Attach your IDE's remote debugger to port 5005. The connection survives restarts because curie relaunches the JVM with the same arguments.

Stopping

Press Ctrl-C. The signal is forwarded to the application process, and both curie and the JVM exit.

Flags

FlagDescription
--offlineUse only locally cached artifacts; do not access the network.
-- <args>Arguments forwarded to the Java application.
